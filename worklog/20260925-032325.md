部署过程：

1. 检查实际运行的 Compose、容器挂载、Nginx 配置、证书和续期钩子；以服务器实际配置为准。
2. 备份旧项目、配置、数据与证书，使用 SQLite backup 接口生成一致性数据库快照，并通过完整性检查。
3. 在本地构建静态网站，打包 42 个正式文件，生成 SHA-256 校验清单并上传到独立版本目录。
4. 在服务器核对全部文件校验和。
5. 使用现有 Nginx 镜像和相同挂载测试候选配置，通过后原子切换 `current` 链接。
6. 原位写入已挂载的 Nginx 配置，再执行 `nginx -t` 和平滑重载。
7. 验证服务器实际返回的首页与发布文件完全一致，再进行公网浏览器和 HTTP 检查。
8. 清理上传包、临时校验文件及 ACME 探针；保留发布版本、备份和校验清单，关闭本次 SSH 连接。

Nginx 配置使用单文件 Docker 挂载，所以配置更新采用原位写入，避免重命名换 inode 后容器继续读取旧文件。部署阶段设置了失败恢复逻辑，本次切换成功，未触发回滚。

原 Django 容器 `kultalabweb-web-1`、数据库与媒体卷保留原样，用于回滚。新网站请求由 Nginx 直接处理，无需新建 Node 或 Django 服务。
